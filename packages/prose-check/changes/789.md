The check finds the filler the house voice rules out, an en dash used as a dash, a placeholder left in and an emoji, reads `.jsx` files and finds more semicolons joining clauses. A repository that moves to this version may find lines written before it.

- **Rules.** A trailing -ing clause, an inflated word, an empty opener, a canned closer, a wordy phrase, an intensifier, a leftover placeholder, an en dash used as a dash and an emoji are each a rule of their own, with every word that has a technical meaning in code or docs left out. A semicolon after a digit, a closing bracket or a quote joins clauses as one after a letter does. `.jsx` files are read, and a page's code samples are left alone, as Markdown's inline code is.
- **Command.** A passing run says every file it read follows every rule, rather than naming the rules.
- **Docs.** The README lists every rule with an example, says what each kind of file has read, shows a failure as text, covers CI, a pre-commit hook and every export, and opens with the kit's badges and links. The package's description names the new rules.
- **Tests.** Each new rule finds the lines it names and passes the lines that only look like them, `.jsx` comments are read, and a semicolon after a digit, a bracket or a quote is found while a page's code sample is not.
