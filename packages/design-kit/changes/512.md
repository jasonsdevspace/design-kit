A refused form says the first field's name and error on the status line, so a visitor on VoiceOver for iOS hears what is wrong, and a reset that clears errors says so.

- **Controls.** A refusal that moves focus to a field, or finds focus already on it, says the field's name and its error, with how many fields need attention where more are wrong, such as "Player name: Error: Enter a value.". VoiceOver on iOS reads a field's error only as a hint, after a pause, which other speech cuts off and which a visitor who turns hints off never hears, and focus moved by script may not land, so the error is always said. A screen reader that reads the error as focus lands hears it twice. A refusal that moves focus to a summary still says nothing over it. A reset that goes through, where any field was in error, says "Form cleared.", since focus stays on the button and the errors go out of hearing, and a reset of a form with nothing wrong, as after a save, says nothing.
- **Docs.** The reference's refused form section says what a refusal and a reset say and why, and the comments of `attachForm` and `useFormRefusal` say the same.
- **Tests.** Browser tests in a page without React, through `useFormRefusal` and inside a shadow root hear the field's name and error, with the count where more are wrong, for a field focus moves to, one already focused, a set the kit draws, a set described on its fieldset alone, a field marked in error with no error drawn and a box alone in a section, and hear "Form cleared." after a reset that clears errors and nothing after one that clears none.
