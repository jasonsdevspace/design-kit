A page refused through `useFormRefusal` or `attachForm` can build an error summary that lists a
stepper showing its own error, with the words the stepper shows.

- **Upgrading.** `invalid` is called with two arguments. A page that hands it a function with a
  second parameter of its own, such as a flag with a default, or that reads a rest parameter or
  `arguments.length`, gets the second list there, and wraps the function to take the first list
  alone. A second parameter typed as something else fails the type check.
- **Controls.** `attachForm` calls `invalid` with a second list, `invalid(failures, shown)`, which
  holds every failure in the form's order, each with its field, its control and the words its field
  shows: the form's words for a failure in the first list, and a stepper's own range error's words
  for one left out of it. The first list stays as it was, so a page that draws every failure it is
  handed never draws a second error on a stepper, and a page that takes one argument is unchanged. A
  summary that already has focus as a form is refused has the first field's name and error said,
  with the count where more are wrong, as a field that already has focus does, where the summary's
  text was said run together, or its own text where no field is marked, and a summary that cannot
  take focus, hidden, inert, out of sight or not focusable, is passed over for the first field in
  error.
- **React.** `useFormRefusal` hands its `invalid` the same second list.
- **Docs.** The reference's refused form section builds its summary from the second list, and
  record 21 says why the second list was chosen over marking the stepper's failure as drawn.
- **Tests.** Browser tests in Chromium, WebKit and Firefox refuse a React form with an empty
  required field and a stepper typed past its range, build a summary from the second list, and find
  the stepper listed with its own words and focus on the summary, and say the first field's name and
  error with the count once the summary already has focus. They find a plain form attached with
  `invalid` handed both lists, with the stepper's words read past a hidden start nested in its error
  and its lines joined, and a summary hidden by an ancestor or a style, made inert or not focusable,
  passed over, and a focused summary's own line said where no field is marked. A set's failure in a
  summary is keyed and linked by its field. The package's type check types the second list, with a
  page that takes one argument still compiling.
