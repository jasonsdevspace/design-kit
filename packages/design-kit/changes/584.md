A toast, a dialog or a panel hands focus back to any HTML or SVG element that takes focus, such as a
link in an inline chart.

- **Controls.** The handback the toast, the dialog and the panels share focuses an SVG element as it
  does an HTML one. Focus that came into a toast from a link inside an inline svg, or was on one as
  the message came, goes back there, a dialog opened from one returns focus to it, and a closing
  panel can hand focus to one that follows it, its address written with `href` or `xlink:href`, or
  to the place on the page that one pressed inside the panel goes to. The panel tells an SVG link by
  its name rather than its class, so a page's unit tests in jsdom, which has no class for an SVG
  link, close a panel without an error. A press on a link written with `xlink:href` counts as a
  press for `focusOnArrival`. A dialog's `returnTo` may give any HTML or SVG element that takes
  focus. `moveFocus` and `focusOnArrival` land through the same helper, so an SVG target or fallback
  takes focus too.
- **React.** A request `useFocusAfterDraw` makes late, once its component has gone, lands on an SVG
  target in sight rather than waiting for it.
- **Docs.** The reference's sections on taking a control down, on moving focus after a change and on
  the toast, and record 23, say a handback can land on any HTML or SVG element that takes focus,
  such as a link in an inline chart, and record 23 gives the controls' new weight, which record 13
  sets at a budget of 19.25 KB. Record 19 says the panel spec runs in Firefox too, where the case
  that goes back into the panel after a press outside reaches the link by focusing it, since Firefox
  sends Shift and Tab from a panel a press focused to the page's body.
- **Tests.** Browser tests in Chromium, WebKit and Firefox find focus back on a link inside an
  inline svg that focus came into a toast from once Escape on its Close dismisses it, on one that
  had focus as the message came where focus then came into the toast from nowhere, and on one that
  opened a dialog once the dialog closes. They find focus sent to one that follows a panel whose
  buttons are gone, one written with `xlink:href` among them, and to the place on the page that one
  pressed inside a panel goes to, a panel closing without an error in a window with no class for an
  SVG link, and a late `useFocusAfterDraw` request landing on one. The dialog and panel specs run in
  Firefox too.
