Options count as given only where a key other than `signal` has a value, so an attach called again
with `{}` or with its other keys left undefined keeps the options it had, and the status line joins
a later attach the way every other attach does.

- **Upgrading.** A page that attached a piece again with `{}`, or with every key but `signal`
  undefined, to put its options back to their defaults now keeps the options it had. It gives one
  option the value it has by default instead, as `{ stay: false }` for a dialog attached to stay,
  and the options it gives replace the last whole, so every key it leaves out goes back to its
  default too.
- **Controls.** An attach called again with an empty object, or with options whose every key but
  `signal` is undefined, as a page spreading its own optional props passes, keeps its holder's last
  options rather than replacing them, while `null` and `false` still count as values, and only the
  options' own keys are read. `attachStatus` joins a later attach the way every other attach does,
  and a status line behaves as it did.
- **Docs.** The reference's section on taking a control down and its section on the dialog, the
  dialog's doc comment and record 23 say which options count as given.
- **Tests.** A unit test finds an empty object, keys left undefined and keys only inherited taken
  for no options, and `null` and `false` taken for options given, and a browser test finds a dialog
  attached to stay still staying once attached again with `{}`, and no longer staying once attached
  again with `{ stay: false }` or with options that leave `stay` out.
