Options count as given only where a key other than `signal` has a value, so an attach called again
with `{}` or with its other keys left undefined keeps the options it had, and the status line joins
a later attach through the same helper as every other attach.

- **Upgrading.** A page that attached a piece again with `{}` to put its options back to their
  defaults, such as a dialog attached to stay, names the value instead, as `{ stay: false }`.
- **Controls.** An attach called again with an empty object, or with options whose every key but
  `signal` is undefined, as a page spreading its own optional props passes, keeps its holder's last
  options rather than replacing them, while `null` and `false` still count as values.
  `attachStatus` joins a later attach through the shared teardown helper, and still attaches afresh
  a line let go of while still attached, with no other change to how a status line behaves.
- **Docs.** The reference's section on taking a control down and record 23 state the rule for
  options given by their values.
- **Tests.** A unit test finds an empty object and keys left undefined taken for no options, and
  `null` taken for options given, and a browser test finds a dialog attached to stay still staying
  once attached again with `{}`.
