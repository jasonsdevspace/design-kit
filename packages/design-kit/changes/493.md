- **Upgrading.** A form attached with `attachForm` or `useFormRefusal` now takes `noValidate` from script, and the kit checks the browser's constraints on submit before the page's handler, which runs only where every field passes. A React page passes `invalid` to `useFormRefusal` and sets its errors from the failures it is handed. A page that handled the browser's check itself takes that code out.
- **Controls.** `attachForm` sets `noValidate` on a form it attaches, or on the form around an attached part of one, so a page without script keeps the browser's check. On a submit it reads each field's `validity`, and where any fails it stops the submit, draws each error as the kit's field draws one and refuses, or hands the failures to `invalid`. A button marked `formnovalidate` submits unchecked, and errors the kit drew go once their fields pass. Each failure takes the field's own words, as `data-error-value-missing`, else the page's `errorWords`, else the kit's, which say what to do. Fields not in error are marked `aria-invalid="false"` as the form is attached. A refusal passes over a control marked off, itself or by its set, and where no field in error can take focus it leaves focus where it is and says the first error with the count. New types `Failure`, `FailureWords` and `FieldFailure` describe the failures. Record 13 sets the controls' budget at 14.25 KB by its rule.
- **React.** `useFormRefusal` takes `invalid` and `errorWords`, and refuses after the render that draws the failures it handed the page.
- **Docs.** Record 21 says why the kit checks the browser's constraints itself, with the research and the options weighed. The reference shows the check, the words and how a field or a page replaces them, and says a form is attached as it is drawn and why `required` stays.
- **Tests.** Browser tests in Chromium, WebKit and Firefox refuse a form that fails its constraints before the page's handler, take errors away once their fields pass, submit unchecked from a `formnovalidate` button, take each failure's words in turn, mark fields not in error before a submit, and hand the failures to a React page that draws them. Others refuse a form written without `noValidate`, a set whose first control is off and a set off as a whole.
