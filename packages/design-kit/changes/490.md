A view's heading takes focus on arrival only when a visitor's press or submit brought the view.

- **Controls.** `focusOnArrival(heading, { from })` moves focus to a view's heading as it arrives, as `moveFocus` does, only where a press or submit has been made since a view last took focus, so a page's first draw, an arrow along a row of tabs, a Tab press and a second view drawn for the same press take nothing. It counts presses with one listener on the document, from its first call, and a request called off before it lands is as if never made.
- **React.** `useArrivalFocus` decides through `focusOnArrival`, so it no longer takes focus from a roving row of tabs whose views use it, nor after the visitor only tabbed, adds no listener as it draws again, and calls its request off as its view leaves, so a view gone in the frame it arrived in moves nothing.
- **Docs.** The reference says the hook is for a view a press brings, as a tab bar's, and names `focusOnArrival` for a page without React. Record 20 says the hook keeps only its key and leaves the decision to `./controls`.
- **Tests.** Browser tests arrow along a roving row of tabs whose views take focus on arrival and find focus on each tab, find focus where Tab left it for a view drawn late, find nothing moved for a view gone in its first frame, and count one listener for presses after many draws.
