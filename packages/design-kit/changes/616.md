A React field's error keeps working when the page draws it again while the kit refuses the form.

- **Upgrading.** A page that holds on to an error it drew for a field finds it hidden and without its
  id while the kit refuses that field, since the kit's error stands in its place and takes the id.
- **Controls.** Where a field already holds an error the page drew, with the field's id followed by
  `-error`, `attachForm` hides it and draws its own error just before it with that id, rather than
  writing its words into the page's error. The page's children are never moved, so React drawing
  the field again with new words, an address among them, throws nothing and leaves the kit's words
  shown. Once the field passes, the kit's error goes and the page's comes back with its id and
  whatever React drew in it meanwhile. The control's `aria-describedby` still names the same id, so
  a screen reader hears one error, the kit's while the refusal stands.
- **Docs.** The reference's section on refusing a form says how the kit's error takes the place of
  one the page drew.
- **Tests.** A browser test in Chromium, WebKit and Firefox refuses a React field that holds an
  error, draws the field again with new words, plain and with an address, and finds no exception,
  the kit's words shown and described while the refusal stands, and the page's newest words back
  once the value is fixed. The form tests run in Firefox as well. The test of an error a page drew by
  hand finds one error shown for the field, the page's own hidden with its words kept.
