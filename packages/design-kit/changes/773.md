A form submitted inside an open shadow root counts as a press, so a view its submit brings for the first time focuses its heading.

- **Controls.** The kit hears a submit inside each open shadow root that focus enters, that a key or a click passes through, or that holds a node the kit reads focus through, by a listener on the root itself, since a submit never leaves the root its form is in. That covers an open root inside a closed one the kit hears, and one focus already sat in as the kit loaded, on the page or in a frame of the page's own origin, and a field that sends its own form once a phone fills in a code. Before, the page never heard such a submit, so the view a submit inside a widget's open root brought took no focus. A form a script submits inside an open root that focus has not entered since the kit loaded, that no key or click has passed through and that holds no node the kit reads focus through still counts for nothing, and so does one inside an open root within a closed root the kit has not read focus in.
- **Docs.** Record 19 says so and names the cases it leaves, and the reference says so in its section on focus on arrival.
- **Tests.** Browser tests submit a form inside an open shadow root in Chromium, Firefox and WebKit, by Enter in its field, by Enter or Space once focus is on its submit button, by a pointer on that button, by a script after a click in the root or after focus entered an open root inside a closed one, by its own field once a code is filled in, by a script where its field had focus before the kit loaded, on the page and in a frame, and by a script beside a heading the kit reads focus through, and find the view the submit draws for the first time taking focus. A form a script submits in a root focus never entered brings its view with no focus, and the next submit after a click there brings focus.
