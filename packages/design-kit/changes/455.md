The reference shows a failure with Try again, built from a live callout and its actions.

- **Docs.** The reference's Callouts section shows the danger callout a page mounts empty with `role="alert"`, drawn from a new example, and a React part that loads its products and fills the callout when the load fails. Try again sits in the actions, so the alert reads the failure and never the button. It empties the callout and puts the loading line back, outside the callout, while the load runs again, and `useFocusAfterDraw` sends focus to the part's heading. A failure is put in a moment after the callout empties, so one that comes back at once is still heard, and it moves no focus, since focus moved as an alert is read would cut it short or read it twice. A block of TSX in the reference can be written from a file in the examples module, marked by `<!-- source: name -->`, so the React part a page copies is the one the type check and the browser tests run.
- **Tests.** Browser tests in Chromium and WebKit mount the reference's own part and find the callout empty and out of sight, the first failure filled with no focus moved, no button words in the alert, the same failure heard twice with focus left on the heading and the next Tab on Try again, a failure that comes back at once put in after a pause, and the list drawn with the callout emptied when the load works. The filled failure stays whole on a 320px phone at twice the text size in Chromium and under wider spacing, with no audit findings in both themes and in forced colors.
