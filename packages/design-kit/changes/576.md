A focus request asked from inside an open dialog lands where the page asked as the dialog closes.

- **Controls.** A dialog attached by `attachDialog` keeps the focus the browser hands back as it
  closes as the kit's own handback, so a `moveFocus` request asked in the task that closes the
  dialog, takes it from the page or takes it down lands on its target rather than being taken for
  the visitor's move once the browser has put focus on the opener.
- **Docs.** The reference's dialog and record 23 say that a `moveFocus` request asked in the task
  that closes a dialog sends focus to its target rather than to the opener, whether that task closes
  the dialog, takes it from the page or takes it down, and that one asked in an earlier task, such
  as before an awaited save, finds the page behind still inert, so focus goes to the opener.
- **Tests.** Browser tests open a dialog from an opener with focus on it, ask `moveFocus` from
  inside it, then close it, close it and take it down, or take it from the page and take it down in
  the same task, and find focus on the element asked for in Chromium, WebKit and Firefox.
