A focus request asked from inside an open dialog lands where the page asked as the dialog closes.

- **Controls.** A dialog attached by `attachDialog` keeps the element the browser hands focus to
  as it closes as the kit's own handback, the moment focus leaves the closed dialog, and its close
  event hands focus back only where focus is still on that element, in the dialog or on the body. A
  `moveFocus` request asked in the task that closes the dialog, takes it from the page or takes it
  down lands on its target, whenever the close event comes and when an answer's form closes the
  dialog, and focus the page moves itself in that task stays.
- **Docs.** The reference's dialog and record 23 say that a `moveFocus` request asked in the task
  that closes a dialog sends focus to its target rather than to the opener, whether that task closes
  the dialog, takes it from the page or takes it down, and that one asked in an earlier task, such
  as before an awaited save, finds the page behind still inert, so focus goes to the opener.
- **Tests.** Browser tests open a dialog from an opener with focus on it and ask `moveFocus` from
  inside it, then close it and take it down, take it from the page and take it down, close it with
  its close event coming after the request's frame, or press an answer whose form closes it, and
  find focus on the element asked for, and find focus the page sets in the closing task kept, in
  Chromium, WebKit and Firefox.
