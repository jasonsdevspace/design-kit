A focus request asked from inside an open dialog lands where the page asked as the dialog closes.

- **Controls.** A dialog attached by `attachDialog` keeps what had focus as it opened, which the
  browser hands focus back to as the dialog closes. A `moveFocus` request treats focus there as free
  while the dialog is closed and its close not yet handled. A request that lands there takes that
  place from the dialog. The dialog's close event and its takedown hand focus back by one test,
  where focus is still on that element or by the rule every piece hands it back by. So a request
  asked in the task that closes the dialog, takes it from the page or takes it down lands on its
  target, whenever the close event comes. This holds when an answer's form closes the dialog, when
  the pressed control is taken away as it is pressed and when the opener is not what had focus.
  Focus the page moves itself in that task stays. A dialog closed and taken down in one task hands
  focus to its opener as a plain close does.
- **Docs.** The reference's dialog and record 23 say that a `moveFocus` request asked in the task
  that closes a dialog sends focus to its target rather than to the opener, whether that task closes
  the dialog, takes it from the page or takes it down, and that one asked in an earlier task, such
  as before an awaited save, finds the page behind still inert, so focus goes to the opener.
- **Tests.** Browser tests open a dialog from an opener with focus on it and ask `moveFocus` from
  inside it. They close it and take it down, take it from the page and take it down, close it with
  its close event coming after the request's frame, press an answer whose form closes it, or take
  away the pressed control as it is pressed and close it, and find focus on the element asked for.
  Focus the page sets in the closing task stays. Others open it from an opener that is not what had
  focus, and find a request for what had focus landing there through a late close event, and focus
  going to the opener from a dialog closed and taken down in one task. Another asks for two places
  as a toast with focus in it is taken down and finds focus on the later one. All run in Chromium,
  WebKit and Firefox.
