A page moves focus to a control once a change is drawn, with fallbacks, and a view puts focus on its heading when a visitor's press brings it.

- **Controls.** `moveFocus(target, { fallbacks })` focuses an element or an id a frame after the request, passes over a target that is gone, hidden, inert, disabled or off for the first fallback that takes focus and then the app frame's body or the page's main content, by the walk a closing panel hands focus back by, leaves focus a visitor has moved since the request, drops a request a second old, and returns what calls it off.
- **React.** `useFocusAfterDraw()` returns that function, the same across renders, the last request taking the place of one not yet landed and a request not yet landed called off when the component unmounts. `useArrivalFocus(key)` returns a ref for a view's heading, which takes focus on an arrival a visitor's press brought, as `focusOnArrival` decides.
- **Docs.** The reference has a section on moving focus after a change, record 19 notes the walk the panels and `moveFocus` share, record 20 covers hooks over a function that acts once, and the README names the hooks.
- **Tests.** Browser tests find an id drawn after the request focused, a target gone, hidden, inert or off passed over for a fallback or the main content, focus a visitor moved left alone, a request called off, a control asked for twice focused twice, the last of two requests in one frame focused, a removed control's focus moved to the next or to a heading, and a heading focused when its key changes or a press draws its view, but not as the page first draws or over a field the view focuses.
