A page moves focus to a control once a change is drawn, with fallbacks, and a view puts focus on its heading when a visitor's action brings it.

- **Controls.** `moveFocus(target, { fallbacks })` focuses an element or an id a frame after the request, passes over a target that is gone, hidden, inert or disabled for the first fallback that takes focus, by the walk a closing panel hands focus back by, leaves focus a visitor has moved since the request, and returns what calls it off.
- **React.** `useFocusAfterDraw()` returns that function, the same across renders, calling off a request not yet landed when the component unmounts, and `useArrivalFocus(key)` returns a ref for a heading that takes focus when the key changes, never as the page first draws.
- **Docs.** The reference has a section on moving focus after a change, and record 19 notes the walk the panels and `moveFocus` share.
- **Tests.** Browser tests find an id drawn after the request focused, a target gone, hidden, inert or off passed over for a fallback, focus a visitor moved left alone, a request called off, a control asked for twice focused twice, a removed control's focus moved to the next or to a heading, and a heading focused when its key changes but not as the page first draws.
