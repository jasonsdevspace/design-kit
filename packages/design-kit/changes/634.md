A dialog puts back a page's own `closedby` as it is let go, and the behavior code loses the loose
ends the audit before 0.9.4 marked.

- **Upgrading.** A dialog taken down puts back the `closedby` the page gave it before it was
  attached, where it took it away before. A page that gave its dialog a `closedby` and counted on
  the takedown to leave none sets the attribute it wants after the takedown.
- **Controls.** A dialog taken down puts back the page's own `closedby`, whether it was attached to
  stay or not, before it hands focus back, so a page that attaches it again as focus goes back keeps
  what that attach sets. A `closedby` the page set while it was attached without `stay` stays, while
  one that options given since took away gives way to the page's own. The teardown can hand an
  attach options with keys missing, and its type says so. The rest is tidied with no change in
  behavior: a dead arm of the stepper's marking, a comment from when there were two maps,
  `AttachOptions` declared once, a type parameter that hid the DOM's `Element`, one loop that
  follows focus into shadow roots, the document position named, ids read through one helper, a name
  that hid the panels' list of buttons, an unreachable guard in the status line and a record named
  as the records beside it are. The panels keep the visitor's last place once the last button is
  let go, since a page that draws its only button again lets the old one go before the new one is
  attached, and a comment says so.
- **Docs.** The reference says a dialog taken down puts back the page's own `closedby`, and which
  `closedby` the page set while it was attached stays.
- **Tests.** Browser tests put back a page's own `closedby` as a dialog attached to stay, and one
  attached without it, is taken down, keep one the page set while the dialog was attached without
  `stay`, and leave a dialog attached again from its own takedown with the `closedby` that attach
  set.
