The controls find what an id names in the root an element lives in, and follow focus into a shadow root, so a widget drawn inside one finds its own parts.

- **Controls.** `moveFocus` and `focusOnArrival` given an id look for it in the root where focus was when they were asked, and fall back to the main content of that root before the page's. The form's refusal, its errors and hints, a stepper's range and progress's label look for the ids they read in their own element's root, so a widget never reaches an element of the page around it that shares an id. What has focus is followed into a shadow root that holds it wherever the controls read it, so a dialog, a toast, the theme switch and a group of rows inside one hand focus back and on as in a page, and a press inside a shadow root counts toward an arrival. A panel and its button are still found from the page's document, which the panel listens on.
- **Docs.** The reference says an id is looked for in the root where focus was, and that a panel is found from the document.
- **Tests.** Browser tests in Chromium, WebKit and Firefox refuse a form inside a shadow root and hear its field's error, move focus by an id there past a host element sharing it, name progress by a label there, focus a view's heading named by an id there on an arrival a press brought, and fall back to the widget's own main content.
