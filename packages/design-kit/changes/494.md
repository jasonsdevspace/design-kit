The controls find what an id names in the root an element lives in, so they work inside a shadow root as they do in a page.

- **Controls.** `moveFocus` given an id looks for it in the root where focus was when it was asked, and the form's refusal, its errors and hints, a stepper's range and progress's label look for the ids they read in their own element's root, so a widget drawn inside a shadow root finds its own parts and never an element of the page around it that shares an id. What has focus is followed into a shadow root that holds it, so a request from inside one lands. A panel and its button are still found from the page's document, which the panel listens on.
- **Docs.** The reference says an id is looked for in the root where focus was, and that a panel is found from the document.
- **Tests.** Browser tests in Chromium, WebKit and Firefox refuse a form inside a shadow root and hear its field's error, move focus by an id there past a host element sharing it, and name progress by a label there.
