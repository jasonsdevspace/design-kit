The controls read focus from the page down through frames of its own origin, so a dialog and a panel
the page attaches inside such a frame hand focus back there as they do on the page.

- **Controls.** `activeOf()` follows focus into each frame of the page's own origin that has it, to
  the control focused there or the frame's body, as it follows a shadow root, and every piece, the
  stepper and a focus request read that one view. `attachDialog` on a dialog inside such a frame
  hands focus back as it closes to the control in the frame that opened it, or to the page's own
  button that opened it, where it went to the frame or nowhere. `attachPanel` on a button inside
  such a frame listens in the frame's document, so the button opens and closes its panel and focus
  goes back to it, where a press there did nothing, and a panel in the frame and one of the page
  with the same id stay apart. A dialog or a panel the page closes in a frame while the visitor is
  on the page leaves focus where they put it. A button the page made and moved into the frame works
  alike. A toast hands focus back to the control inside a frame within a frame, where it went to the
  inner frame. Each stays in the document it was attached in, so a page that moves one into another
  takes it down and attaches it again. A dialog in a frame makes only that frame inert, so a page
  that needs the whole view held opens the dialog on the page.
- **Docs.** The reference's dialog, panel, toast and focus sections say how each reads focus inside
  a frame the page drives, and records 19 and 29 have amendments for it.
- **Tests.** Browser tests attach a dialog, a panel and a toast inside a frame from the page and
  find focus handed back to the control in the frame or the page's own opener as each closes, focus
  left where a visitor moved it as the page closes one, panels of the same id kept apart, a toast's
  hand back into a frame within a frame, and the frame's listeners coming off at takedown and once
  the frame has left the page.
