A focus request asked by id from a widget's shadow root finds an id in the page's own markup.

- **Controls.** `moveFocus` and `focusOnArrival` look an id up in the root where focus was, then in
  each root around it out through the hosts to the page, so a widget's button in a shadow root that
  asks for a heading in the page's markup focuses that heading, where focus fell to the page's main
  content, and a widget's own id still wins over the same id on the page. A request asked with focus
  in a frame inside a shadow root finds its id on the page too.
- **React.** A late request from `useFocusAfterDraw`, asked by a component in a shadow root once it
  has gone, finds an id only the page holds by the same walk, where it was held and never landed.
  `useArrivalFocus` finds an id as `focusOnArrival` does.
- **Docs.** The reference's "An id inside a shadow root" and "Moving focus in React" and record 19
  say where an id is looked for, from an open, a nested and a closed shadow root and from a frame
  inside one.
- **Tests.** Browser tests find a heading on the page focused from a widget's button in an open
  shadow root and in a nested one, a widget's own id found before the page's, the page's element of
  an id a closed shadow root shares found from that root, an id on the page found with focus in a
  frame inside a shadow root and by a late request from a component in a shadow root since gone,
  and a page with a form or a frame named `host` finding its id with no page error. A check finds no
  module of the controls asking `'host' in` a root.
