The tokens ship in the Design Tokens Community Group's format, for a tool that reads it.

- **Tokens.** `tokens.resolver.json`, exported beside the sheets, holds the tokens in the format's
  2025.10 edition as one resolver document: a base set with every token the two themes share, and a
  theme modifier with each color and shadow in a light and a dark context, light by default. A
  length in `em`, a keyword and a value the browser works out as it draws, by `min()`, `max()`,
  `calc()` or `env()`, stay in `tokens.css` alone. A token renamed in the file is a breaking change,
  as a custom property renamed in the sheet is.
- **Docs.** The reference says what the file holds and which tokens it leaves to the sheet, and the
  package README lists it with the other exports.
- **Tests.** A test draws each token in the file back as CSS and holds it to what `tokens.css`
  declares on the root, fails on a token in one file and not the other, and names why each token the
  format cannot write is left out. The smoke test loads the file from the packed package.
