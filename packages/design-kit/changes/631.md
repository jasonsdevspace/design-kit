A closing panel searches the page for what follows it only where no button takes focus.

- **Controls.** A panel that closes tries the place its last link went to and its buttons first,
  and looks through the page for what follows it only where each of those refuses focus, in the
  same walk, so a page's own listener that moves focus still ends it. Since 0.9.3 every close that
  handed focus back queried every element of the page that takes focus first, which a page of many
  links paid for on each close. A key that is not Escape reads nothing of where it was pressed.
- **Docs.** Record 19 says the search for what follows the panel is made only once the buttons
  have refused focus.
- **Tests.** Browser tests in Chromium, WebKit and Firefox find no search of the page as a panel's
  button takes focus and one where both buttons are off, and find a key that is not Escape reading
  its path no more often with panels attached than with none.
