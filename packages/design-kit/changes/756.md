The React hooks read where focus was inside a closed shadow root through an element they hold.

- **React.** `useFocusAfterDraw` reads where focus was through its target where that is an element, `useFormRefusal` through the form a refusal is for, the newest for the page's own and each form for its own failed submit, and `useArrivalFocus` through its heading once it is drawn, so inside a closed shadow root a visitor who moves to another control there before a request lands is left there.
- **Docs.** The reference's section on where focus can be says what each hook reads where focus was through inside a closed root, that a move into another closed root or a target given as an id or a function is read as no move. Its section on an id inside a shadow root says `useFocusAfterDraw` given an element target there finds its fallbacks' ids inside the root.
- **Tests.** Browser tests land a `useFocusAfterDraw` request inside a closed shadow root, focus a `useArrivalFocus` heading there as its key changes and a `useFormRefusal` form's first field in error, and find focus left where it moved inside the root before any of them lands, still there some frames later, and a row that removes itself there finds the next, in Chromium, Firefox and WebKit.
