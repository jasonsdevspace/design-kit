The React hooks take their controls down through ref callbacks that return their cleanup, and a focus request asked as its component unmounts still lands.

- **React.** Each hook's ref makes an `AbortController` as its element arrives, hands its attach the `signal` and returns the cleanup that aborts it, which React 19 calls in place of calling the ref with null, so a row of cells, a busy button, progress, a form's check and a provider's line are each taken down by their attach's own teardown. A ref called with null by a helper that merges refs does nothing. Under `StrictMode` in development, the second run takes each control down and attaches it afresh, with nothing doubled or dropped. `StatusProvider` still waits a microtask before it aborts its line's signal and keeps the line attached where it comes back, so words said in a first effect stay through that run, and the function `useStatus` returns keeps speaking, and says nothing once its provider has gone. `useFocusAfterDraw` waits for the render of a request asked as its component first draws, from a ref on its own markup too. A request still waiting when its component unmounts, or when an `Activity` hides it, is made then, with where focus was read as it was asked, so a row that asks for focus on the next one as its press removes it moves focus there, at once, after an await, from a timer or in a transition. Nothing at unmount calls a focus request off, and `moveFocus` lands it only where focus is still where it was or has fallen to the page's body, so a visitor who moved on keeps their place. A request in a transition an urgent update overtook lands before the transition draws, on its fallbacks where the transition draws its target. A request asked after the component has unmounted takes focus only from the page's body, whatever `from` it was given. A refusal still waiting as its form's component unmounts is called off, and one ref on two forms keeps refusing through the other as one goes.
- **Docs.** Record 20 is amended for the hooks' ref cleanups, with `StatusProvider`'s wait and the focus requests around an unmount, and names the ways of telling a stale request apart that were rejected. Record 22 says a focus request lands when its component unmounts before the request is drawn. The reference says how a hook takes its control down and when a focus request asked around an unmount lands.
- **Tests.** Browser tests in Chromium, WebKit and Firefox find focus on the next row as a row asking for it is removed at once, after an await, from a timer and in a transition, a request whose transition was overtaken landing where focus fell, leaving a field the visitor moved to and going to its fallback where the transition draws the target, a request whose component an `Activity` hides landing unless focus moved, a request made in one commit landing as the next takes its component away, a field a view asks for from its own ref focused, and focus left on the next screen for a late request, whatever place it names. Browser tests draw the hooks under `StrictMode` in React's development build and find words said in a first effect kept on the provider's line, its function speaking after that run and a new provider's after it is drawn afresh while the old one stays silent, one arrow key moving one cell, a busy notice, the end of a progress and a refusal each said once, nothing said once the pieces leave, a ref called with null doing nothing, a form given back, its `noValidate`, marks and listeners gone, as the ref moves to another form, only the second of two requests a part makes as it first draws taking focus, a refusal still waiting as its form leaves saying nothing, and one of two forms on a ref taken away leaving the other refusing. The focus tests run in WebKit and Firefox as well as Chromium.
