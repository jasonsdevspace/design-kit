The React hooks take their controls down through ref callbacks that return their cleanup, and a focus request asked as its component unmounts still lands.

- **React.** Each hook's ref makes an `AbortController` as its element arrives, hands its attach the `signal` and returns the cleanup that aborts it, which React 19 calls in place of calling the ref with null, so a row of cells, a busy button, progress, a form's check and a provider's line are each taken down by their attach's own teardown. A ref called with null by a helper that merges refs does nothing. Under `StrictMode` in development, the second run takes each control down and attaches it afresh, with nothing doubled or dropped. `StatusProvider` still waits a microtask before it aborts its line's signal and keeps the line attached where it comes back, so words said in a first effect stay through that run, and the function `useStatus` returns keeps speaking, and says nothing once its provider has gone. `useFocusAfterDraw` waits for the render of a request asked as its component first draws, from a ref on its own markup too, and lands a request asked in the task that unmounts its component, so a row that asks for focus on the next one as its press removes it moves focus there. A request asked earlier and still waiting, as in a transition an urgent update overtook, or whose component an `Activity` hides, is called off, and a request asked after the component has unmounted takes focus only from the page's body, so a visitor already on the next screen is left where they are.
- **Docs.** Record 20 is amended for the hooks' ref cleanups, with `StatusProvider`'s wait and the focus request asked at unmount. The reference says how a hook takes its control down and when a focus request asked around an unmount lands.
- **Tests.** Browser tests remove a row that asks for focus on the next one as it goes and find focus there, find focus left on the next screen's field where a request comes after its component unmounted, find focus on a field a view asks for from its own ref as a press first draws it, and find a request asked in a transition called off when an urgent update unmounts its component or an `Activity` hides it. Browser tests draw the hooks under `StrictMode` in React's development build and find words said in a first effect kept on the provider's line, one arrow key moving one cell, a busy notice, the end of a progress and a refusal each said once, nothing said once the pieces leave, a ref called with null doing nothing, the provider's function speaking after the second run and a new provider's after it is drawn afresh while the old one stays silent, and a form given back, its `noValidate`, marks and listeners gone, as the form's ref moves to another form.
