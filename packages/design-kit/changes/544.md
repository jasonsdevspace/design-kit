The React hooks take their controls down through ref callbacks that return their cleanup, and a focus request asked as its component unmounts still lands.

- **React.** Each hook's ref makes an `AbortController` as its element arrives, hands its attach the `signal` and returns the cleanup that aborts it, which React 19 calls in place of calling the ref with null, so a row of cells, a busy button, progress, a form's check and a provider's line are each taken down by their attach's own teardown. A hook keeps every element its ref is on, so one ref on two forms, rows of cells or bars keeps the one left refusing or taking new options as the other goes, and a ref called with null by a helper that merges refs and drops the cleanup takes every element down. Under `StrictMode` in development, the second run takes each control down and attaches it afresh, with nothing doubled or dropped. `StatusProvider` still waits a microtask before it aborts its line's signal and keeps the line attached where it comes back, so words said in a first effect stay through that run, and the function `useStatus` returns keeps speaking, and says nothing once its provider has gone. `useFocusAfterDraw` waits for the render of a request asked as its component first draws, from a ref on its own markup too. A request still waiting when its component unmounts, or when an `Activity` hides it, is made then, with where focus was read as it was asked, so a row that asks for focus on the next one as its press removes it moves focus there, at once, after an await, from a timer or in a transition. Nothing at unmount calls a focus request off, and `moveFocus` lands it only where focus is still where it was or has fallen to the page's body, so a visitor who moved on keeps their place. A request in a transition an urgent update overtook lands before the transition draws, on its fallbacks where the transition draws its target. A request asked while an `Activity` hides the component is held and lands once it shows, and one asked after the component has gone is never made, since React does not tell the two apart, where it was made at once before. A refusal still waiting as its form's component unmounts is called off, a microtask later so a refusal asked as the form first draws lands through React's second run in development.
- **Docs.** Record 20 is amended for the hooks' ref cleanups, with `StatusProvider`'s wait and the focus requests around an unmount, and names the ways of telling a stale request apart that were rejected. Record 22 says a focus request lands when its component unmounts before the request is drawn. The reference says how a hook takes its control down and when a focus request asked around an unmount lands.
- **Tests.** Browser tests in Chromium, WebKit and Firefox find focus on the next row as a row asking for it is removed at once, after an await, from a timer and in a transition, a request whose transition was overtaken landing where focus fell, leaving a field the visitor moved to and going to its fallback where the transition draws the target, a request whose component an `Activity` hides landing unless focus moved, a request made in one commit landing as the next takes its component away, a field a view asks for from its own ref focused, a request asked while an `Activity` hides its component held until it shows, and a request asked after its component has gone dropped. Browser tests draw the hooks under `StrictMode` in React's development build and find words said in a first effect kept on the provider's line, its function speaking after that run and a new provider's after it is drawn afresh while the old one stays silent, one arrow key moving one cell, a busy notice, the end of a progress and a refusal each said once, nothing said once the pieces leave, a ref called with null taking each piece down, a form given back, its `noValidate`, marks and listeners gone, as the ref moves to another form, only the second of two requests a part makes as it first draws taking focus, a refusal still waiting as its form leaves saying nothing, a refusal asked as its form first draws landing, and, with one ref on two forms or two rows of cells, the one left still refusing or taking new options whichever is taken away. The focus tests run in WebKit and Firefox as well as Chromium.
