The React hooks take their controls down through ref callbacks that return their cleanup, and a focus request asked as its component unmounts still lands.

- **React.** Each hook's ref returns the cleanup that takes its control down, which React 19 calls in place of calling the ref with null, and a ref called with null by a helper that merges refs does nothing. A row of cells, a busy button and progress are let go by the cleanup, and a form keeps what `attachForm` set on it, its cleanup only stopping refusals through it. Under `StrictMode` in development, the second run leaves nothing doubled or dropped. `StatusProvider` still waits a microtask before it lets its line go and keeps the line where it comes back, so words said in a first effect stay through that run. `useFocusAfterDraw` waits for the render of a request asked as its component first draws, from a ref on its own markup too, and lands a request asked in the task that unmounts its component, so a row that asks for focus on the next one as its press removes it moves focus there. A request asked earlier and still waiting, as in a transition an urgent update overtook, or whose component an `Activity` hides, is called off, and a request asked after the component has unmounted takes focus only from the page's body, so a visitor already on the next screen is left where they are.

Browser tests draw the hooks under `StrictMode` in React's development build and find words said in a first effect kept on the provider's line, one arrow key moving one cell, a busy notice, the end of a progress and a refusal each said once, nothing said once the pieces leave, and a ref called with null doing nothing.
