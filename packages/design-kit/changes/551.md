A stepper attached with a value past its limits shows its error at once, with nothing said.

- **Controls.** `attachStepper` shows the stepper's error as it attaches, and again when a form's reset brings the value back, when the value is outside the limits or between steps, describes the field by it and marks it invalid, and says nothing on the status line, so a page that draws that state, as the kit's site does, writes no code of its own for it. A field drawn blank, a field that is disabled or read only, and a field showing the page's own error show no error as the page loads, and the error is cleared as before once the value is right or the stepper is taken away. The error now names only a value outside the limits, between steps or missing, so a refusal a page sets with `setCustomValidity` no longer shows the stepper's error, as it attaches or once the value is changed.
- **Docs.** The reference and the attach function's comment say when a value drawn past the limits shows the error and when it does not.
- **Tests.** Browser tests attach a stepper past its limit and find the error shown, the field described by it and marked invalid, and its status line empty, then find the error cleared by a right value, by taking the stepper away and by a form's reset, and find a field attached blank with no error. Others find the error back once a reset brings back a value drawn past the limit, none on a disabled or read-only field, none for a refusal the page sets, and the page's own error alone where it shows one.
