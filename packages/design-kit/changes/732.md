Focus inside a frame of the page's origin held by a frame of another origin is read where it is.

- **Controls.** Where the walk down from the page reaches a frame of another origin, it looks through the frames that frame holds, which the page reaches by their windows, for the frame of the page's origin that has focus, and reads on inside it. An element there is seen at the page's level as the frame of another origin that holds it, kept by its window as the reader goes through, so one inside a closed shadow root is found too, and a piece in a frame beside it lifts it the same way. While the browser's window itself has no focus, focus there reads as the frame of another origin. So a panel, a stepper, a toast and a dialog there hand focus back to the control that had it, and a request asked from there finds its id on the page.
- **Docs.** The reference's section on where focus can be says focus in such a frame is read where it is.
- **Tests.** A browser test hands focus back to a panel's button in a closed shadow root that holds such a frame. The focus grid's squares for a frame of the page's origin inside one of another origin pass for every piece in Chromium, Firefox and WebKit, and none is listed as failing.
