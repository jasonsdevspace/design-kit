The controls ship in parts a page's bundler can split, so a site that loads one piece's code on one
page sends it to that page alone.

- **Controls.** Behind the same `./controls` entry, each piece's code is an internal module of its
  own, and the state two pieces share, the presses, the focus the kit hands back and the checked
  forms, sits in one module that adds the listeners as it loads, so every part on a page reads one
  copy. No export, type, option or behavior changes. The package names `dist/state.js` beside
  `dist/controls.js` in its `sideEffects`, so a bare import keeps the listeners. What a page's
  bundler sends, without comments and gzipped, before and after:

    | What a page imports      | Before       | After        |
    | ------------------------ | ------------ | ------------ |
    | Every function           | 22,519 bytes | 22,435 bytes |
    | The module imported bare | 706 bytes    | 729 bytes    |
    | `attachTable` alone      | 2,012 bytes  | 2,036 bytes  |
    | `attachForm` alone       | 8,879 bytes  | 8,871 bytes  |

- **Docs.** Record 13 gives the controls' module layout, its `sideEffects` and the controls' size
  before and after the move.
- **Tests.** A unit test builds pages together and finds each page's chunks without another's
  piece: the form beside the table, the busy button beside the toast, and a focus request beside
  the dialog. Others find the shared state kept on a bare import, nothing sent for any other
  internal module imported bare, no part importing another and no cycle among the modules, every
  part that keeps a registry attached in the teardown table, and the React modules reaching the
  controls only through the entry. The browser tests serve every module of the controls.
