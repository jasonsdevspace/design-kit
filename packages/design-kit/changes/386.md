A panel a button opens is attached by its button, so its corner Close needs no script of the
page's own.

- **Controls.** `attachPanel(button)` opens and closes the panel the button names in
  `aria-controls`, every attached button that names it following, closes it by its corner Close
  with focus back on the button that opened it, and returns a `PanelControl`, whose `set`, a
  `SetPanel`, opens or closes it from the page's own code and whose `detach` lets the button go.
  One listener on the page serves every panel and comes off once every button is let go. A button
  with no `aria-controls` is refused, and a Close in later content that reuses a panel's id leaves
  the panel alone.
- **Docs.** The reference's corner Close attaches its panel with `attachPanel`, the README lists it,
  `PanelControl` and `SetPanel`, and the controls' budget is 7.25 KB, set by the budgets' rule with
  it in place.
- **Tests.** Browser tests open and close a panel by its button and its Close, by keyboard and
  pointer, with focus back on the button, keep two buttons in step, close a panel drawn again past
  a handler that stops the press, move focus out of a panel closed by the page's code, return the
  same for a button attached twice, start a panel as its button says whatever the markup says,
  move focus to the main content where nothing after the panel takes it, leave a panel alone when
  a Close in later content that reuses its id is pressed, let every button go and take the
  listener off only with the last, leave a button attached again alone when what it returned
  before is detached, hand focus back to the button whose `set` opened the panel, and back to the
  button that opened it when another button's `set` closes it, follow a button the page points at
  another panel, and audit the page with the panel open and closed.
