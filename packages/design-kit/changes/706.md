A stepper, a form, a grid of cells and a table the page attaches inside a frame of its own origin
work there as they do on the page, and a focus request asked from inside a frame leaves a visitor's
move in it alone.

- **Controls.** `attachForm` on a form inside such a frame checks and refuses it, where it let the
  submit through with nothing checked, and focus moves to the summary or the field in error in the
  frame. `attachStepper` there keeps a button that has focus shown as its value turns read only and
  hands focus to its value or its box in the frame as it is taken down, where the button hid and
  focus fell to the frame's body. `attachRoving` there gives the grid its one stop and moves by its
  arrows, where it found none of the frame's cells, and hands focus on to the next cell where the
  one with focus is taken out, on a page whose body a visitor can type in too. `attachTable` there
  brings a link out from under a pinned column as the keyboard reaches it. The form, the grid and
  the table tell the frame's controls by their names and node types rather than the page's classes.
  A focus request reads where focus was once, as it is asked, and compares where focus is as the
  frame's document sees it, so a visitor's move between two of its controls counts as a move, and a
  body no one can type in, the frame's or the page's around it, still counts as free. Its id and the
  home it falls back to are looked for on the page, whether or not the page passes `from`, and one
  asked from a frame that loads another page before it lands compares as the page sees it. A field's
  language is read past a shadow root inside a frame as it is past one on the page, and a frame with
  no language of its own reads in the page's.
- **React.** `useFocusAfterDraw`, `useArrivalFocus` and `useFormRefusal` take where focus was as a
  request does, so a request or a refusal asked from inside a frame leaves a visitor's move in it
  alone.
- **Docs.** The reference's form, stepper, grid, table, theme switch and focus request sections say
  how each works inside a frame the page drives, and record 19's decision covers the stepper, the
  form, the grid and a request asked from a frame.
- **Tests.** Browser tests attach a form, a stepper, a grid and a table inside a frame from the page
  and find a refused submit moving focus to the field in error with the kit's error and the page's
  status line, a stepper's focused button kept as its value turns read only and focus handed to its
  value or its box as it is taken down, the grid's stop and arrows and focus handed on from a cell
  taken out, and a link brought clear of a pinned column. Browser tests find a request asked from
  one control of a frame, through `moveFocus` and through the React hooks, leaving focus on another
  the visitor moved to, a request given a control in a frame as `from` finding its id on the page,
  and a request landing after its frame loads another page or the page hides the frame. Unit tests
  read a field's language past a shadow root of a frame's, from the frame's own document and then
  the page's, and find no part of the kit but the focus module calling `activeOf`.
